# 桂备菜 · 操作文档

> 适用版本：v1.5.0 ｜ 阅读对象：运营人员、门店管理员、系统管理员
> 本文档按"从装好到日常使用"的顺序编写，跟着做即可上手。

---

## 一、环境准备

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10+ / macOS / Linux |
| Python | 3.10 ~ 3.14（推荐 3.11） |
| 内存 | ≥ 4 GB（首次训练预测模型时建议 8 GB） |
| 网络 | 预测需联网拉取天气数据（Open-Meteo，免费）；AI 备菜建议需配置 LLM API Key |

1. 安装依赖：
   ```bash
   cd 桂备菜项目目录
   pip install -r guibeicai/requirements.txt
   ```
2. 初始化配置目录（生成 `.env`，首次必做）：
   ```bash
   python cli.py init
   ```
3. 编辑 `guibeicai/.env`，填入 LLM API Key（不填也能跑预测，只是没有 AI 文字建议）。

## 二、启动系统

| 命令 | 作用 | 访问地址 |
|---|---|---|
| `python cli.py web` | 仅启动 Web 界面 | http://localhost:8501 |
| `python cli.py scheduler` | 仅启动后台定时预测 | 无界面 |
| `python cli.py all` | 同时启动界面 + 定时预测 | http://localhost:8501 |

> 生产部署建议用 `all`，让系统每天自动跑预测；演示/调试用 `web` 即可。
> 登录账号由管理员在"系统管理 → 用户管理"中创建。

## 三、登录与首页

1. 浏览器打开 http://localhost:8501，输入账号密码登录。
2. 登录后进入**工作台首页**：
   - 顶部 4 张指标卡：累计预测次数 / 预估营业额 / 食材成本 / 平均毛利率；
   - 中部"近期预测记录"表 + 预估营业额趋势图；
   - 底部 6 个快捷入口（数据上传、执行预测、食材预测、采购单、预测对比、损耗分析）。
3. 右上角可切换**明/暗主题**（侧边栏顶部的 ☀️/🌙 按钮）。

## 四、日常操作主线（推荐顺序）

### 1. 数据上传（首次 / 补数据）
- 进入 **数据上传** 页面。
- **批量导入**：下载模板 → 在 Excel 的两个 Sheet（销售数据、菜品用料表）中填好数据 → 上传。系统自动校验列名、匹配门店、补录菜品用料（recipes）。
- **每日销量录入**：选门店 + 日期（默认昨日，可补近 7 天），填实际销量；系统三级兜底：已录入 > 预测 > 历史均值。

### 2. 执行预测
- 进入 **执行预测**：
  - **手动预测**：选门店 + 预测日 → 点"开始预测"，调用 Prophet + LLM 生成结果；
  - **自动预测**：APScheduler 每日定时跑（时间可在配置中改），无需手动。
- 预测结果含：各菜品预测份数、食材采购明细、风险等级、采购建议。

### 3. 查看预测（预测总览）
- 进入 **预测总览**，按门店/日期筛选历史预测，看财务指标；
- 点某行 → 看详情（营业额/毛利率、风险、采购建议、采购明细），可导出 CSV。

### 4. 食材级预测 ★新增
- 进入 **食材预测**，选门店 → 自动读取最近一次预测 → 按 recipes 把菜品份数聚合到食材维度；
- 看：食材需求明细（分类/用量/单位/成本）+ Top15 成本图 + 导出 CSV。

### 5. 生成采购单 ★新增
- 进入 **采购单**，选门店 → 一键生成 → 看食材种类、采购数量、预估金额；
- 渠道场景下可在「渠道工作台」按「供货范围」拆分已覆盖 / 未覆盖需求，导出 CSV 后发给对应渠道商或导入 ERP。

### 6. 损耗分析 ★新增
- 进入 **损耗分析**，选门店 + 日期区间 → 看总损耗量、综合损耗率、损耗成本；
- 菜品损耗排行 + Top15 损耗成本图 + 导出 CSV。

### 7. 智能预警 ★新增
- 进入 **智能预警**，点"刷新预警" → 看四类预警清单：
  - 加备（预测 > 1.3× 历史均值）
  - 减备/滞销（预测 < 0.7× 历史均值）
  - 节假日备货（未来 3 天含法定节假日）
  - 偏差复核（实际与预测偏差 > 30%）
- 处理完可"标记已处理"。
- **预警自动推送**：门店可在「门店管理」开启"预警自动推送"并配置「老板邮箱 / 企业微信 Webhook」；系统每日 06:30 自动把命中预警（邮件 + 企微）推送给老板，无需老板登录系统。也可在预警页点"立即推送"手动补发。

### 8. 预测回测与误差反馈 ★新增
- 进入 **预测回测**，选门店（全部门店 / 单店）+ 回测窗口(holdout 天数, 默认 7) + 最少历史天数(默认 30) → 点"运行回测"；
- 系统用 Prophet 时间序列做 hold-out 回测，输出**整体指标**：平均绝对误差 MAE、平均绝对百分比误差 MAPE(%)、均方根误差 RMSE、平均偏差、覆盖菜品数；并给出**逐菜品明细**；
- **误差反馈闭环**：点"应用偏差校正"→ 给每个菜品写入偏差校正因子（限幅 0.5~1.5）→ **下次预测自动纠偏**，模型越用越准；
- 页面下方保留历史回测记录，便于跟踪模型改善。

### 9. 系统运行规则（自动化）
- **每日自动预测**：Web 后台启动调度器（APScheduler）后，每 5 分钟巡检一次；对「参与自动预测」的活跃门店，按该店配置的 `每日预测时间`（默认 **06:00**，可由环境变量 `SCHEDULER_HOUR/MINUTE` 或每店独立配置覆盖）到点且当天未跑过，则自动预测其目标日（由 `预测目标日` 决定，默认明天），并自动推送采购单。
- **每日预警推送**：调度器默认 **06:30** 对各「开启预警自动推送」的门店生成预警，命中即经邮件 / 企微推送给老板（同日同店仅推送一次，防刷屏；可在预警页「立即推送」手动补发）。
- **预测失败告警**：门店连续预测失败达到阈值，系统通过邮件 / 企微通知系统管理员排查。
- **账号有效期**：用户可设生效 / 失效日期（按合同期限），未生效或已过期账号无法登录与使用。
- **数据库备份**：调度器默认每月 1 日 03:00 自动备份（时间可由 `DB_BACKUP_*` 环境变量调整）。

## 七、常见问题排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 启动报 `No module named 'guibeicai'` | 不在项目根目录运行 | `cd` 到项目根目录再执行 `python cli.py ...` |
| 预测卡住 / 报错 stan_backend=None | Windows 下 cmdstan 解码问题 | v1.5 已内置修复（monkeypatch），确保用的是最新 `_forecast.py` |

| 想重跑演示数据 | — | 运行 `python scripts/gen_demo_data.py`（幂等，可重跑） |

## 九、数据初始化（新客户 / 门店快速录入）

> 场景：谈下一家渠道商或门店后，要把"门店 + 菜品 + 食材 + 配方"等一大批基础数据快速录进系统；以及**部署生产前清空全部演示/测试数据**。
> 入口：**数据初始化**页（仅管理员，左侧「数据管理」分组）。每类数据支持「下载 CSV 模板 → 填好 → 上传导入」，并可在页内一键清空测试数据。
> 角色分工总览：管理员建账号+分配角色+设有效期+管合同；**渠道商**录入旗下门店并配置该门店的食材供货范围；**门店**在「数据上传」页导入历史销量、在「菜品管理」维护菜单与配方（或批量导入）。

### 9.1 各角色的数据责任

本系统面向三类角色分工协作：

| 角色 | 负责的数据 | 入口 |
|---|---|---|
| **管理员** | 账号新建、角色分配、账号有效期（按合同期限）、合同管理 | 用户管理 / 角色管理 / 合同管理 |
| **渠道商** | 录入旗下门店；配置每家门店的「食材供货范围」（门店需多种食材、渠道只供其中几样）；自建并管理旗下门店账号 | 渠道门店与供货、渠道门店账号（「渠道」分组） |
| **门店** | 历史销量（训练预测模型）；菜品清单与配方/BOM（食材需求与采购单来源） | 数据上传 / 菜品管理 |

> 渠道商本质是聚合对账层，不自供货；其"只供几样"通过「供货范围」表达，系统据此在渠道工作台拆分已覆盖 / 未覆盖需求。

> 注：原「授权管理」页已移除，用户→角色的分配直接在「用户管理」（管理员）与「渠道门店账号」（渠道商）页面完成；渠道商在「渠道门店账号」页只能建/管「商家用户」角色，且门店限定在自身权限范围内（归属统计见该页）。

### 9.2 系统当前支持的录入方式

| 数据 | 录入方式 | 备注 |
|---|---|---|
| 门店 | ✅ CSV 批量导入（数据初始化页，本节） | 也支持渠道门店与供货页（渠道商）逐条建并自动绑定 |
| 菜品配方 / BOM | ✅ CSV 批量导入（数据初始化页，本节） | 导入即自动建菜品+食材，**不依赖大模型** |
| 门店供货范围 | 渠道门店与供货页勾选 / 手工补录 | 按归一化食材名记录"该门店渠道可供给的食材子集" |
| 历史销量 | ✅ Excel 批量导入（数据上传页） | 导入后**新菜自动创建**，并可自动生成配方、回灌预测历史（见 9.7） |
| 用户 / 角色 / 合同 | 手工（用户管理 / 角色管理 / 合同管理） | 账号与合同数量少，手工即可 |

> 历史销量导入在「数据上传」页；门店 / 菜品配方 BOM 批量导入在「数据初始化」页，均**幂等**（重复导入同名记录走更新，不重复建）。

### 9.3 推荐录入顺序（依赖关系）

```
1. 管理员建账号 + 分配角色（admin / 渠道商 / 门店用户），按需设账号有效期、签合同
2. 门店        ← 其他数据都依赖门店（渠道商在「渠道门店与供货」录，或数据初始化批量导）
3. 菜品配方BOM ← 自动建菜品+食材（先把菜单/配方定下来，预测才好用）
4. 供货范围    ← 渠道商在「渠道门店与供货」勾选每家门店可供给的食材（可选，未覆盖部分在渠道工作台提示）
5. 历史销量    ← 在「数据上传」页导入，触发预测（POS 自动对接可免手工导入，见 9.7）
```

### 9.4 CSV 模板字段

各模板可在「数据初始化」页点「下载模板」获取（UTF-8-SIG，Excel 直接打开不乱码）。

**① 门店**（`门店` 必填，`城市` 必填）

| 列 | 说明 |
|---|---|
| 门店 / 省份 / 城市 | 同名同省市视为同一家；城市必填 |
| 老板邮箱 / 企微Webhook | 采购单推送渠道，可空 |
| 自动预测 | `是`/`否` |
| 预测时间 | `HH:MM`，默认 `06:00` |
| 预测目标日 | `今天`/`明天`/`后天` |

**② 菜品配方(BOM)**（`门店`+`菜品`+`食材`+`每份用量` 必填）

| 列 | 说明 |
|---|---|
| 门店 / 菜品 | 菜品不存在自动创建 |
| 菜品单价 | 可选，导出采购单用的售价 |
| 食材 / 品类 / 每份用量 / 单位 | 同一(门店,菜品)多行=该菜完整配方 |
| 食材单价 | 可选，写则作为该食材初始估价 |

> 导入会**整体替换**该菜品配方（覆盖式），方便修正后重导。

> **量纲规范**：系统统一以 **kg（固体/干货/生鲜/禽蛋等）** 和 **L（液体）** 为唯一标准单位。
> - 导入时若写 `g`，程序会自动除以 1000 换算为 `kg`（如 500g → 0.5kg）。
> - 若写 `ml`，程序会自动除以 1000 换算为 `L`。
> - 计数单位（个/只/片/份）没有固定重量，系统自动按 `0.05kg/个` 估算并转为 kg；
>   建议这类食材在 CSV 里直接按重量写 kg，避免估算偏差。
> - LLM 自动生成配方时，已强制要求输出 kg/L，禁止返回 g/ml/个。

### 9.5 清空测试数据（生产割接）

「数据初始化」页底部**危险区**：

1. 确认当前业务数据量（页内显示门店/菜品/食材数）。
2. 在输入框输入确认短语 **`清空测试数据`** 解锁按钮。
3. 点「清空全部业务数据」。

> 该操作**永久删除**门店 / 菜品 / 销量 / 预测 / 配方 / 食材等业务数据，**保留用户、角色、权限、合同与审计日志**（账号与合同需随真实客户重新配置）。
> 典型流程：演示验证完毕 → 清空 → 按 9.3 顺序用真实数据重新录入 → 跑预测验证。

### 9.6 上线检查清单

- [ ] 真实门店已建（数据初始化 / 渠道门店与供货）
- [ ] 菜品 + 配方已录入（菜品管理可看到每道菜的食材明细与成本）
- [ ] 历史销量已导入且覆盖足够周期（预测总览有数据；或 POS 自动对接已联调）
- [ ] 渠道商账号已建并绑定旗下门店、供货范围已配置（渠道工作台可登录看到汇总与覆盖情况）
- [ ] 账号有效期 / 合同已按真实合同期限设置（合同管理页可同步有效期到关联账号）
- [ ] 测试数据已清空（如为生产环境）
- [ ] 管理员默认密码已修改（首次启动会创建 `admin/admin`，务必改密）

### 9.7 账号有效期与合同管理（管理员）

- **账号有效期**：在用户管理页为每个账号设置「生效日期 / 失效日期」（按合同期限）。不在有效期内的账号登录会被拒绝，API 调用返回 403；留空=长期有效。
- **合同管理**（仅管理员，左侧「系统管理」分组）：登记客户/渠道合同（编号、名称、金额、支付方式、甲乙方、签订/生效/到期日、附件、备注），可将合同「生效/到期日」一键**同步到关联账号有效期**，实现"合同到期即账号停用"的自动化管控。
- **POS 自动对接**：开启后，渠道/门店的销售数据可无人值守地自动建档新菜、自动生成配方、并将实际销量回灌为预测历史，无需每次手工导入（详见 POS 对接页配置）。
