## 三、部署步骤

1. **环境准备**：Python 3.14 + 依赖（`guibeicai/venv` 或等价环境，需 `streamlit / pandas / prophet / cmdstanpy / chinese_calendar / plotly / pyyaml / python-dotenv`）。
2. **配置密钥**：复制 `guibeicai/config/settings.example.env` 为 `guibeicai/.env`，填入真实 `SILICONFLOW_API_KEY`、`WEATHER_API_KEY`、`EMAIL_PASSWORD` 等（`.env` 已被 `.gitignore` 忽略，切勿提交）。
3. **启动应用**：`streamlit run guibeicai/web/app.py`（建议绑定 `0.0.0.0` 与固定端口，置于反向代理后）。
4. **定时调度**：`app.py` 启动时会拉起 APScheduler 每日定时预测（时间由 `SCHEDULER_HOUR`/`SCHEDULER_MINUTE` 控制，默认 06:00）；单实例文件锁防止重复执行。
5. **数据库迁移**：`init_db()` 在每次页面/调度启动时自动执行，`audit_log` 等表以 `IF NOT EXISTS` 幂等创建（真实库 `data/guibeicai.db` 本次已手动执行迁移验证，表已存在）。

## 八、配置项 → 文件 → 启用条件映射

> 本章回答「某个配置该写在哪里、是否必填、改了生不生效」。

### 8.1 配置生效来源（重要澄清）

本项目采用 **12-factor**：**所有真正生效的配置都在 `guibeicai/.env`（环境变量），由 `config/settings.py` 读取；数据库相关配置在 `data/guibeicai.db`（表字段）。**

⚠️ **已知偏差（待修复）**：`settings.py` 的 `_load_yaml("config/config.yaml")` 路径少拼了一层 `guibeicai`——它从项目根拼成 `项目根/config/config.yaml`，而文件实际在 `项目根/guibeicai/config/config.yaml`。**后果：`config.yaml` 与 `config/stores.yaml` 当前实际未被 `settings` 加载（`_config={}`、`stores` 返回 0 家）**。程序此前能正常运行，是因为其余配置全部走了 `.env` + 数据库 + 代码硬编码默认值。
- 这意味着：本节列出的生效配置**只认 `.env`**，不要去 `config.yaml` 改值（改了也不生效，除非先修该路径 bug）。
- 修复建议（如需让 `config.yaml` 真正生效）：把 `_load_yaml` 的基目录改为 `Path(__file__).resolve().parent`（即 `guibeicai/config/`），调用处相应改为 `self._load_yaml("config.yaml")` / `self._load_yaml("stores.yaml")`。**但该修复会让 `config.yaml` 的部分配置突然生效，可能改变行为，需单独回归验证，不在本次清理范围内。**

## 九、渠道商（配送商）角色与渠道工作台（2026-09-08 新增）

### 9.1 背景与定位

商业模式为 **B2B2B**：**门店使用**（做预测、生成采购单），**渠道配送商付费**（3~8 万/年）。
配送商购买的不是预测工具，而是「下游门店需求可前置 → 库存损耗下降 + 客户不流失」，
因此必须为付费方提供**跨店汇总视角**，否则付款人看不到价值、续费无依据。

### 9.2 实现内容

| 项目 | 落点 | 说明 |
|---|---|---|
| 新增角色「渠道商」（`code=channel`） | `roles` 表（`角色管理` 页可建） | `pages=["dashboard","channel_overview"]`，权限全 false |
| 新增「渠道」页面分组 | `web/_pages.py` `PAGE_GROUPS` | 侧边栏分组顺序：首页 / 智能预测 / 数据管理 / **渠道** / 分析 / 系统管理 |
| 新增页面 `18_渠道工作台.py`（`channel_overview`） | `web/pages/` | 跨店食材需求汇总 + 门店活跃度 + 单店下钻 + CSV 导出 |
| 跨店汇总纯函数 `aggregate_cross_store` | `web/_ingredient_forecast.py` | 复用 `build_purchase_order`，按 (食材, 单位) 合并 |
| 门店活跃度统计 `get_prediction_stats_by_stores` | `web/_db.py` | 返回最近运行时间、最近预测日期、近 7 天预测次数 |
| API 层只读校验 `_assert_writable` | `api/main.py` | 只读角色调写接口一律 403 |

### 9.3 数据隔离与权限边界（已实测）

- 页面层：`get_accessible_stores(user)` —— 管理员看全部门店，渠道账号**仅看 `user_stores` 绑定的门店**；
- 角色层：`roles.pages` 白名单 —— 渠道角色无 `predict_config` / `data_upload` / `store_manage` 等入口，`require_page_access("channel_overview")` 生效；
- API 层：`_assert_writable` —— 渠道账号即使拿到令牌，`/api/predict/run`、`/api/actual-sales`、
  `/api/pos-sources*`（增删改/测试/拉取）、`/api/push/purchase-order` 全部返回 **403**；`merchant` 角色不受影响。
- 鉴权顺序：写接口先做只读校验再查资源，**403 优先于 404**，避免泄露资源是否存在。

### 9.4 配置方式（零代码，页面操作）

1. **角色管理**：新建角色 → 编码 `channel`、名称「渠道商」→ 页面权限勾选「工作台首页」「渠道工作台」→ 其余权限全不勾；
2. **用户管理**：新建用户 → 角色选「渠道商」→ **必须绑定至少一家门店**（非管理员角色的强制校验）；
   已创建演示账号：`channel_demo`（绑定 2 家门店，初始密码首次登录强制修改，验证后可自行删除）；
3. 用该账号登录 → 侧边栏仅出现「工作台首页」「渠道」分组 → 只能看到绑定门店的数据。

### 9.5 已知限制

- **同名不同单位不换算**：如「生姜 g / 片 / kg」分行显示（页面会标注 ⚠️ 并提示推动门店在「食材管理」统一单位），
  这是刻意设计——避免换算错误导致采购量偏差；
- **暂未建 `distributors`（渠道主体）表**：渠道归属沿用 `user_stores`。签约第一家配送商前需补
  「渠道 → 门店」归属关系，才能统计渠道带了多少店、按渠道停用/续费、做白牌；
- 跨店汇总为**只读视图**，暂不含采购单回传配送商、备货建议（待签约反馈后再排期）。

### 9.6 验收项

- [ ] 渠道账号登录后侧边栏只见「工作台首页 / 渠道工作台」，无预测、上传、管理类入口；
- [ ] 渠道工作台「旗下门店 / 有预测门店 / 近 7 日活跃 / 汇总金额」四个卡片数值与门店实际一致；
- [ ] 跨店汇总金额 = 各门店采购单金额之和（抽验 2 个食材的数量也一致）；
- [ ] 切换渠道账号后看不到未绑定门店的任何数据；
- [ ] 渠道账号令牌调写接口返回 403（见 4.x 安全项）。
