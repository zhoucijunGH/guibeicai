# 桂备菜 H5 网页版（手机浏览器访问）设计方案

> 版本：v1.0　日期：2026-09-08　状态：待确认（确认后进入开发）

---

## 一、背景与约束

- **问题**：当前无营业执照，微信小程序认证（需企业/个体户主体）走不通，原规划的"微信小程序"无法上线。
- **转化目标**：改用 **H5 网页版**——店员/老板用手机浏览器直接访问，不依赖微信生态，无需小程序资质。
- **关键利好（经代码调研确认）**：H5 版**不是从零开发**。项目内已存在 `mp/` 这个 uni-app 工程（`build:h5` 可编译出手机端网页），登录走账号密码（复用 WEB 端 users 表、token 鉴权），5 个业务页面与完整后端 API 均已就绪。本次工作量集中在「移除微信依赖 + 构建 + 部署」，**不是重写**。

## 三、技术选型（推荐并默认）

| 方案 | 说明 | 取舍 |
|---|---|---|
| **A. 复用 `mp/` uni-app 构建 H5（推荐）** | 同一代码库 `build:h5` 出静态网页，部署到 Nginx/对象存储 | 零重写、移动端 UI 现成、与后端 API 已联调、token 鉴权就绪；唯一代价是去掉微信登录 UI |
| B. 纯 HTML/JS 从零写 H5 | 另起一套静态站点 | 工作量大、重复造轮子、需重新联调 API；仅在 A 不可用才考虑 |
| C. React/Vue 独立 SPA | 更现代但同样重写 | 不必要，uni-app H5 已是标准 Vue3 产物 |

**选型结论**：采用 **方案 A**。理由：已有完整代码、与后端契约一致、工期最短、风险最低。

## 五、后端改动（基本为零）

- 现有 FastAPI 已放开 CORS、`/api/login` 账号密码鉴权就绪，**无需改代码**。
- 部署建议（增强安全，可选）：将 `allow_origins=["*"]` 收紧为具体 H5 域名（如 `https://h5.guibeicai.com`），防止任意站点盗用接口。
- 若需"记住我/刷新 token"：当前 token 为 HMAC 长期有效，H5 复用即可，暂不改。

## 六、部署架构（推荐方案）

### 方案 A：单云服务器 + Nginx（推荐，最省心）

```
用户手机浏览器
      │  https://h5.guibeicai.com   （同域，无跨域）
      ▼
   云服务器（2C4G）
   ├─ Nginx
   │   ├─ 静态目录 → /usr/share/nginx/h5  （mp/dist/build/h5 产物）
   │   └─ 反代 /api → 127.0.0.1:8000  （FastAPI）
   └─ FastAPI（uvicorn, 127.0.0.1:8000，不对外直暴露）
```

- **同域部署**：H5 与 `/api` 同域名，浏览器同源、无跨域、CORS 无需特殊配置，登录页"服务器设置"可留空。
- **HTTPS**：Let's Encrypt / 云厂商免费证书（已有，见成本）。
- **H5 产物更新**：重新 `build:h5` → 上传 `dist/build/h5` 到 Nginx 静态目录即可，后端不动。

### 方案 B：H5 放对象存储/CDN（可选，降服务器负载）

- 静态产物传 COS/OSS + CDN（不同源），需 CORS 已 `*`（当前已满足）或配置具体域名。
- 适合访问量大时；MVP 阶段用方案 A 即可。

## 七、域名与 ICP 备案（重点合规，必须先办）

> 公网访问**必须 ICP 备案**，而备案**必须有主体**。无营业执照时主体选择如下：

| 主体 | 能否备案 | 成本 | 适用 | 风险/限制 |
|---|---|---|---|---|
| **个体工商户执照** | ✅ 可备案 | 注册基本免费/代办几百元，无年费 | **推荐**：主体一致（域名/服务器/备案统一），可开对公/个人卡收付款，比个人备案合规 | 主体变更难（前轮已说明），但本项目主体即你本人，可控 |
| **个人备案** | ✅ 可备案（仅需身份证） | 0 | 无执照的权宜之计 | 个人备案网站性质须为"非经营性"，对外商用/交易受限，被认定经营可能被注销；桂备菜是 30 家门店 B 端工具，存在合规灰度 |
| 企业执照（国企/公司） | ✅ 最稳 | — | 当前无 | 你明确无执照，不采 |

**建议**：既然要做正式商业化 H5，**办一张个体工商户营业执照**（成本低、可备案、主体一致），比个人备案稳。这与上一轮"要不要先搞个体户"的考量一致——小程序不搞了，但个体户执照对"域名备案 + 未来收付款"仍价值在。

**备案时序（务必提前）**：ICP 备案 7~20 个工作日，需域名主体 = 服务器主体 = 备案主体一致。建议：**先在个体户执照下来后立即提交备案，与前端改造并行**。

**替代（免备案）**：H5 部署到**境外服务器（香港/新加坡）**，国内访问略慢、数据出境需谨慎（餐饮经营数据属一般商业数据，非敏感个人信息大规模出境，风险可控但需评估）。仅在你不愿/不能备案时考虑。

## 八、成本变化（对比原小程序方案）

> 单位：元/年（30 家门店）

| 项目 | 原小程序方案 | H5·国内（个体户执照 + 备案） | H5·境外（香港）免备案 | 说明 |
|---|---|---|---|---|
| 云服务器 2C4G | 199 | 199（含 Nginx） | ~1100（香港 2C4G，区间 936–1260；可选 2C2G ≈550） | 境外贵约 900/年；选 2C2G 缩小至约 350/年 |
| 域名 .com | 65 | 65 | 65（也可 IP 直访省去） | 境外无 ICP 强制 |
| ICP 备案 | 0 | 0（需个体户执照） | 0（免备案） | 境外无需 |
| SSL 证书 | 0 | 0 | 0（Let's Encrypt 全球） | 同 |
| 微信小程序认证 | 300 | 0 | 0 | 均不搞 |
| 个体户执照 | — | 一次性 0~300（非年费） | 0（无需） | 境外免 |
| LLM API（推荐档） | 84 | 84 | 84 | 硅基流动/DeepSeek 全球可达 |
| 推送（企微+邮件） | 0 | 0 | 0 | 同 |
| **固定年成本小计** | **≈648** | **≈348** | **≈1249（2C4G）/ ≈699（2C2G）** | 境外贵约 900 或 350/年 |
| 三年总成本 | ≈1944 | ≈1344（含执照 300） | ≈3747（2C4G）/ ≈2097（2C2G） | — |

**结论**：放弃小程序改 H5，**每年省约 300 元（小程序认证费）**，且免去微信订阅消息的模板申请。两种部署方式：
- **国内（个体户执照 + ICP 备案）**：年固定成本 ≈348 元，最省、数据存境内合规最稳、访问最快；代价是办个体户执照（一次性）+ 等 7–20 天备案。
- **境外（香港）免备案**：年固定成本 ≈1249 元（2C4G）或 ≈699 元（2C2G），比国内贵约 900/350 元/年，但即时上线、无执照、无备案等待；代价是服务器更贵、数据出境需评估（餐饮经营数据属一般商业数据，风险可控）、内地访问延迟略增（香港 ~30–50ms 可接受）。

推荐优先国内备案以控成本；若急于上线且不愿办执照，选境外免备案。详细比价见 `docs/成本估算_20260908.xlsx` 的《H5部署方式对比》sheet。

## 十、风险与待确认点

### 待你确认（决定开发范围）
1. **备案主体**：办个体户执照备案（推荐）？还是走个人备案（有经营限制）？或境外免备案部署？
2. **技术路线**：确认复用 `mp/` 构建 H5（推荐），而非另写纯 HTML？
3. **API 基址**：部署走同域反代（推荐，用户免填服务器地址）？还是保留"服务器设置"手填？
4. **推送方式**：MVP 用企微 Webhook + 邮件（免费，推荐），是否够用？还是后续要加浏览器 Web Push？
5. **是否做 PWA**（添加到主屏、类 App 体验）？进阶增强，非 MVP 必需。

### 风险
- **备案时效**：备案 7~20 天，需与开发并行启动，否则上线被卡。
- **个体户主体变更**：若未来转企业，域名/备案需迁移（前轮已说明，可接受）。
- **H5 vs 小程序体验**：H5 无"桌面图标强提醒/微信内分享"，推送靠企微/邮件；对门店工具影响有限。
- **数据合规**：经营数据存国内服务器、备案主体明确即可；若选境外部署需评估数据出境。
