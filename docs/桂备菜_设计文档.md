# 桂备菜 · 产品设计文档

> 版本：v1.5.0 ｜ 适用：中小餐饮智能备菜系统

## 1. 产品定位

桂备菜是一款面向**中小餐饮（单店 / 连锁）**的 AI 销量预测与智能备菜工具。它把"历史销量 + 天气 + 节假日 + 特殊事件"作为输入，预测未来每日各菜品销量，并自动拆解到**食材采购需求**，帮助商家：

- **降低损耗**：少备不卖、多卖不少；
- **降低采购成本**：按预测精准备货，避免应急高价采购；
- **提升人效**：告别拍脑袋和经验备货，系统一键出采购单。

## 2. 技术架构

```
┌─────────────────────────────────────────────┐
│  前端 (Streamlit 多页面 Web 应用)            │
│   工作台 / 数据上传 / 执行预测 / 预测总览      │
│   食材预测 / 采购单 / 预测对比 / 回测          │
│   损耗分析 / 智能预警 / 门店·菜品·用户管理     │
└───────────────┬─────────────────────────────┘
                │ 业务调用
┌───────────────┴─────────────────────────────┐
│  业务逻辑层 (guibeicai/web)                  │
│  _forecast(Prophet)  _llm(备菜建议)          │
│  _ingredient_forecast(食材聚合)  _alerts     │
│  _backtest(回测+偏差校正)  _audit(操作审计)  │
└───────────────┬─────────────────────────────┘
                │
┌───────────────┴─────────────────────────────┐
│  调度层 (APScheduler) 每日定时预测（单实例锁）│
└───────────────┬─────────────────────────────┘
                │
┌───────────────┴─────────────────────────────┐
│  数据层 (SQLite, WAL 模式)                   │
│  stores / dishes / sales_history / recipes   │
│  date_factors / actual_sales / predictions    │
│  backtest_runs / bias_corrections / audit_log │
└─────────────────────────────────────────────┘
```

- **前端**：Streamlit（Python），多页面 + 侧边栏导航，内置明/暗双主题设计系统。
- **预测引擎**：Facebook Prophet，外生回归量 `temp_mean`/`rain_sum`/`special_event`，含 CN 法定节假日。
- **调度**：APScheduler 每日定时预测；文件锁保证单实例，避免重复跑。
- **存储**：SQLite（WAL + busy_timeout），零运维、易备份、适合中小规模。

## 3. 核心预测模型

预测对象：每个菜品未来 N 日销量（份）。

输入特征：
1. **历史销量序列**（周季节性 + 年季节性 + 趋势）—— Prophet 主体；
2. **天气**（均温 `temp_mean`、降水 `rain_sum`）—— 外生回归量；
3. **节假日** —— Prophet 国家节假日组件（CN）；
4. **特殊事件** —— 寒暑假 / 民俗 / 店铺活动 / 手动标注，作为 0/1 外生变量。

工程要点：
- **模型缓存**：以"训练数据全量 + 回归量 + Prophet 版本"做 MD5 签名，数据不变则复用已拟合模型（`.pkl`），跳过昂贵的 Stan 训练。
- **偏差校正闭环**：回测产出每个菜品的偏差因子（`bias_corrections`），下次预测自动乘入，持续校准。
- **兜底**：历史 < 14 天用均值；Prophet 失败回退历史均值。

## 4. 数据模型（核心表）

| 表 | 关键字段 | 说明 |
|---|---|---|
| stores | id, name, city, status | 门店（多租户根） |
| dishes | id, store_id, name, category, standard_price, status | 菜品主数据 |
| sales_history | store_id, dish_id, sale_date, qty, unit_price, revenue | 历史销量（预测输入） |
| date_factors | store_id, factor_date, temperature, is_holiday, weather_text | 每日天气/节假日因子 |
| recipes | dish_id, ingredient_name, quantity, unit, unit_price, category | 菜品用料（BOM） |
| actual_sales | store_id, dish_id, sale_date, actual_qty, actual_waste | 实际销量/损耗（对比/回测） |
| predictions | store_id, predict_date, result_json | 预测结果（含 dish_predictions） |
| backtest_runs | store_id, window_days, metrics_json | 回测指标 |
| bias_corrections | store_id, dish_name, bias_factor, mape | 偏差校正因子 |
| audit_log | user, action, target_type, detail, created_at | 操作审计 |

唯一约束：`sales_history(store_id,dish_id,sale_date)`、`actual_sales(...)`、`date_factors(store_id,factor_date)`。

## 5. 多租户与权限

- 角色：`admin`（全部权限 + 系统管理）、`商家`（仅授权门店）。
- 门店—用户绑定：`user_stores`；所有数据查询按 `store_id` 过滤。
- 操作审计：登录/登出/预测/回测/用户/门店/菜品增删改均落 `audit_log`。

## 7. 关键设计决策与已知事项

- **cmdstan Windows 修复**：Python 3.14 UTF-8 模式下 `where.exe` 输出按 UTF-8 解码崩溃，已在 `_forecast.py` 导入时 monkeypatch `subprocess.Popen` 注入 `errors='replace'`，覆盖 Web 与调度两条路径。
- **Propheat 版本兼容**：`prophet.__version__` 在 1.4+ 置于模块级，预测签名已改用安全取值。
- **密钥托管**：密钥走 `guibeicai/.env`（已 gitignore）；`settings.example.env` 为模板；启动时做缺失校验（仅告警）。
- **年季节性**：历史 < 730 天时 Prophet 会告警"欠辨识"，模型仍可用；如需更稳可关闭 yearly_seasonality。
